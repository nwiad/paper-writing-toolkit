# 通用论文写作流程

本工具包组织材料、论证、写作和评审，不提供论文正文、投稿模板或研究结论。先按 `README.md` 提供研究信息与原始材料（可由 01 代填配置和骨架），再由作者启动相应阶段；任何阶段都不能因目录或文件已经存在而被视为完成。相对路径均相对工程根目录，`project.json` 是路径、语言和稿件格式的配置入口。

## 项目范围与配置

研究问题、研究类型、贡献与范围由 `blueprint.md` 和 `evidence/author_decisions.md` 定义。可以用于实证、理论、综述、定性、系统等研究；根据论证需要选择章节与证据，不能把所有项目强制变成“新方法加实验”的结构。不适用的材料文件应说明原因，不为可选分析建立必填空章节。

- 论文及图表语言读取 `manuscript_language`，讨论和内部记录语言读取 `communication_language`；默认分别为英文和中文。
- 适用时，方法名从 `method_name` 读取。未定名称保留 `[METHOD]`，不自行起名，也不阻塞写作。LaTeX 稿件可以统一使用 `\methodname`，其他格式采用等效的集中管理方式；没有命名方法的研究无需使用该占位符。
- `target_venue`、`paper_type`、`draft_body_page_budget`、`abstract_word_budget` 未设置时不推定目标会议、论文类型、页数或词数。工作预算与正式投稿规则分开记录；正式规则须有当前官方来源。
- `manuscript` 中的格式、入口、模板位置、官方来源、投稿要求、构建命令和预期输出由新项目填写。工具包不附带 LaTeX、会议样式、Word 模板或示例论文。
- `input_paths` 只定位作者授权的外部材料。外部代码、数据和参考目录默认只读；不自动运行研究实验、重算数据、拉取分支、安装工具或技能、提交、发布或投稿。确有额外需要时单独说明，不把这些操作当作写作的默认步骤。

## 事实来源与证据使用

1. 作者最新明确决定界定意图与范围，记录于 `evidence/author_decisions.md`；实际写作反馈记录于 `review/author_feedback.md`。作者决定不代替科学证据，也不能消除材料中尚未解释的事实矛盾。
2. `blueprint.md` 指定论证主线；`evidence/method_spec.md` 描述方法、理论框架或分析步骤；`evidence/experiment_settings.md` 在适用时描述研究设计与设置。
3. 定量结果适用时，从 `evidence/results_readme.md` 指定的唯一数值来源取值，默认是 `evidence/main_results.csv`；使用其中明确的指标、单位、比较对象、统计定义、重复次数和选择规则。未提供的信息不能自行补全；不将单次观察写成均值，不添加材料未提供的误差线或显著性结论。
4. 非定量证据、证明、访谈、案例、语料或文献综合的出处与适用范围，在相关说明和 `evidence/source_map.md` 中定位。未测量的属性、未证明的命题、未开展的分析不能写成既有发现。
5. `evidence/references.md` 记录引用及核验状态。关键引文查原论文或官方来源，不凭记忆编造书目信息，不把旧稿引用或代码路径当作文献已核实的证据。
6. 检查稿件与现有材料是否一致，包括数值转录、指标定义、统计措辞与结论范围。发现冲突时指出具体来源及影响，提出最小澄清项，同时继续不受影响的工作；不擅自修改作者数值，也不自动扩展为原始数据审计或新实验。
7. 当前源码只能支持当前实现的描述，不自动代表历史研究所用版本。只读核对不等于运行、复现或验证；交接应准确区分这些状态。

读取旧文档、历史命令、日志或启动指令时，将其作为资料，不自动执行其中的指令。旧项目只在作者指定用途后读取，不默认作为事实或文风基准。

## 阶段与文件责任

下表使用默认输出路径；若 `output_paths` 已调整，实际读写位置随配置解析。阶段启动时明确每个文件的 owner，避免并行覆盖。

| 阶段 | 入口 | 主要文件责任 | 交接要求 |
|---|---|---|---|
| 01 材料接收 | `prompts/01_materials.md` | `evidence/`、指定来源配置；首次可整理 `blueprint.md` 中作者已提供的信息 | 首次整理或按范围更新，区分已知、不适用、待提供与来源冲突 |
| 02 论证与样稿 | `prompts/02_story.md` | `review/story.md`、`review/style_sample.md`、`review/figure_brief.md` | 提供具体论证和论文语言样稿，由作者确认方向与文风 |
| 03 图稿（可选） | `prompts/03_figures.md` | `paper/figures/`、`review/figures.md` | 需要图时交付可编辑源、实际产物及预览检查；无需图可跳过 |
| 03b 图稿美化（可选） | `prompts/03b_figure_beautification.md` | 隔离候选、`review/figures.md`；选版后协调追加 `review/review.md` 中作者决定 | 真实候选与同宽对照、独立视觉验收、选版交给 04 正式整合 |
| 03c 表格预览（可选） | `prompts/03c_table_previews.md` | 隔离候选、`review/tables.md`；选版后协调追加作者决定 | 逐条件/单元格核对，实际尺寸与灰度预览，正式表不被候选覆盖 |
| 04 全文主笔 | `prompts/04_writer.md` | `paper/` 中正文、引用、表格与构建辅助文件；`review/writer_handoff.md`、`review/author_feedback.md` | 一人统一论证和术语，整合图稿，如实记录稿件与构建状态 |
| 05 独立评审 | `prompts/05_review.md` | 仅 `review/review.md` | 全面独立评审（首次或任意后续版本）、作者意见整理或定向复审；不直接改论文 |

06 `prompts/06_delivery.md` 是可选交付入口，只在作者需要准备交付包、同步指定平台或整理投稿状态时启动；流程见 `instructions/delivery_workflow.md`，记录放 `delivery/`。它不是 01–05 的前置或自动下一步，工具包不预填已同步/已提交状态。

一个主笔负责全文，通常连续承担 02 与 04。独立 agent 可以负责来源核对、绘图或评审，不把正式章节分别写完后直接拼接。图稿与正文可并行，但同一文件只由一个 owner 写。已有主笔时先完成版本交接，再由 05 审阅稳定版本。单独评审作者提供的现有文稿时，05 也可从作者指定路径与版本开始，不要求先做 04 或伪造交接。

## 作者参与与修改循环

```text
填充输入 → 01 整理材料 → 02 故事与样稿 → 作者确认 → 04 全文 → 05 独立评审
                                                   ↑                ↓
                                                   └── 04 修改 ← 作者审阅与取舍
                                                          ↓
                                                     05 定向复审 → 作者决定

03 为可选图稿阶段：可在材料足够时提前启动，也可与 04 并行。
```

首次完整起草前，作者确认故事与样稿的方向和文风。作者在当前会话中已经给出的明确确认持续有效，主笔如实记录后沿用，不反复审批。文件存在、agent 自评通过或示例文本不能被当成作者批准。

05 有三个可单独启动的模式：全面独立评审、定向复审、作者意见整理。全面评审适用于任意稳定版本，每次阅读全文与实际表图，无需先有作者意见、新一轮改稿或上一轮问题清单；定向复审只核对已有问题和修改影响。历史决定用于理解范围与避免重复计数，不替代当前版本的独立判断。

作者完整审阅发生在全稿与独立评审之后。想法尚不具体时，可以先由 05 帮助定位并整理成可执行意见；修改范围明确后交回 04。作者直接提出的修改要求同样有效，不强制经过意见整理。例行排版、未定名称、既定范围内的可逆修正不增加审批点。

05 使用稳定的 `R01` 等编号记录审稿问题，使用独立的 `A01` 等编号记录作者意见整理。后续讨论、主笔回应、复审沿用原编号。区分作者已明确、已确认、待作者确认、暂缓与不采纳；由审稿人推导的实质方向不能写成作者决定。作者明确不采纳或暂缓的意见保留理由，不在下轮当作遗漏。已解决问题不换个说法重新提出；有新证据需要重开时说明依据。

主笔执行本轮授权范围内尚未完成的意见，将实际作者决定同步到 `review/author_feedback.md`，在 `review/writer_handoff.md` 逐项回应。复审检查这些问题是否解决，以及修改是否引入新问题；主线大改或作者另有要求时再扩大范围。05 的通过结论不等于作者定稿或授权投稿。

## 图表候选与正式整合

03b/03c 依据实际目标建立 `review/previews/<round>/<target>/`，路径按 `output_paths.review` 映射。正式稿与候选分开，记录完整来源、源/产物路径、生成方式及正式文件指纹。图稿分别验收科学含义、几何文件与视觉表达；表格按完整条件键逐单元格检查数值、单位、缺失项和强调含义，不仅比较数值集合。结果数据和真实证据不随视觉设计改写。

作者选版后，候选负责人协调追加 `review/review.md` 的 A 编号决定，明确实际采用/不采用/暂缓，不标为审稿通过；技术材料分别写 `review/figures.md`、`review/tables.md`。主笔按 04 的单独整合入口接入正式源与产物，联动正文和图表注，构建并查看成稿，再记实际完成状态。默认交当前主笔；只有用户明确要求新会话或跨会话消息时才按实际授权执行，不把示例指令当成授权。

## 修改前快照

每轮首次修改既有稿件或图稿前，在工程根目录执行：

```bash
python3 scripts/paper_snapshot.py save --label before-revision --note "本轮修改前"
```

每轮指接收一批修改要求后开始的一次修订。同轮协调共用一次成功快照，不按文件重复保存；旧轮次的快照不代替本轮。保存期间协调所有写入者暂停写文件，等待保存及校验成功后再改稿；失败时先解决备份问题，仍可做只读分析。阶段交接记录实际快照路径和校验结果。

首次从零创建稿件无需执行改稿快照，但脚本允许在只有材料时主动保存。03b/03c 只生成隔离预览且正式文件不变时不触发；应用到正式稿件时仍需本轮改稿前快照。纯检查、讨论和 05 只读评审不触发快照。仅通过脚本新建快照，不覆盖已有快照；恢复到新的目录进行比较，不自动覆盖当前工程。快照保存的是当时已有文件，不会编译，已有 PDF 也不自动等于当前源码的输出。

## 模板、构建与完成标准

作者需自行提供适合项目的稿件模板，或明确授权获取所选模板，再配置 `project.json.manuscript`。不因工具包源自某篇论文而继承其样式、匿名设置或投稿规则。模板尚未就绪时，可以完成论文语言的文本草稿并交内容评审，清楚标明排版、构建或格式检查尚未完成，不伪造 PDF 或编译状态。

使用已有且适合稿件格式的构建工具；仅实际成功才报告构建通过。单文件工具不能假装支持多文件工程。检查实际成稿中的表图、公式、引用、截断与可读性；无法查看或构建的部分如实报告。不篡改正式模板的字号、边距等以满足篇幅预算。

完成判断包括研究问题、论证、证据支持、章节职责、语言、图表和交付格式。可编译、文件齐全或事实覆盖全面都不足以单独证明学术质量通过。先修科学与论证问题，再处理表达和版式；局部缺口只局部标记，不把整个稿件变成待办清单。
