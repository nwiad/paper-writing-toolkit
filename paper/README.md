# 文稿输出位置与模板接入

本目录初始只有说明文件，不包含论文正文、章节模板、LaTeX 类/样式文件、示例引用、会议模板或构建脚本。写作流程可复用，正式论文格式由新项目另行确定。

01/02 的材料和样稿不依赖论文模板。进入 04 后可以先生成文本草稿；完成正式排版、构建和页数检查前应接入相应格式与模板。

1. 作者提供目标格式/模板位置，或明确授权获取选定模板；记录来源与适用要求，不默认任何会议或出版社。
2. 由 04 在本工程内安排稿件入口，避免覆盖已有稿件；存在稿件或图稿时先执行工程快照。
3. 在 `project.json.manuscript` 填写 `format`、`entrypoint`、`template_path`（如需模板）、`template_source_url`、`requirements_url`、`build_command` 与 `expected_output`。所有工程内路径相对工程根目录，入口例如 `paper/main.tex` 或 `paper/draft.md` 仅是路径示例，不代表已有文件或规定格式。模板无需网络来源时记录本地来源即可；不涉及构建的纯文本格式可保留对应字段为 null，并在交接说明。
4. 选择当前环境已支持的构建方式；真实执行后记录结果。配置内的 `build_command` 是说明性字符串，快照脚本不会执行它。不要预填已成功的命令或已有 PDF。
5. 图稿有需要时在 `paper/figures/` 生成实际可编辑源和预览；无需要可跳过 03。已有图稿美化与表格样式探索分别走 03b/03c，候选保存在 `review/previews/`；作者选定后由 04 统一接入正式源与产物，并检查论文内实际效果。

缺少模板时，交接应写“文本稿已完成；正式模板与构建未完成”等真实状态，不能声称已排版、已编译或可投稿。
