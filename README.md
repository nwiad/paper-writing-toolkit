# 通用论文写作工具包

这是一套可复制到新项目使用的写作流程：材料接收、故事与文风确认、图表制作、统一主笔、独立评审，以及按需使用的图表美化和交付管理。初始没有研究内容、实际数据、作者决定、历史评审、论文正文或会议/出版社模板。

**你不用手填所有文件。最少提供项目名、研究问题与范围，以及已有材料或材料位置，就可以让 01 整理配置和证据。** 默认论文与图表用英文、沟通及交接用中文，可改配置。已有论文只想再完整审一遍，可直接使用下方“05：全面独立评审”。

## 1. 新项目从零开始怎么用

### 第一步：复制到新项目目录

保留一份未填的工具包，把整套目录复制到新的写作文件夹，再在该目录工作。`project.json.project_root` 默认 `.`，相对配置所在目录，不需要填写机器专属绝对路径。

### 第二步：放入或指定已有材料

小体积原始材料可以放进 `inputs/`，也可以留在外部位置，只提供路径。下列路径是建议放置方式，不表示工具包已经带有这些文件：

| 材料 | 放哪里/怎么提供 | 是否必须 |
|---|---|---|
| 研究问题、动机、方法/论证思路、研究范围 | `inputs/` 中的说明文档，或直接写在启动消息中 | 至少提供研究问题、范围与已有材料概述 |
| 已有结果表及其定义 | `inputs/results/`，保留原格式；说明单位、统计量、重复定义等已知信息 | 有数值研究结果时；没有则不需要造表 |
| 主要文献、原论文或链接 | `inputs/references/` 或来源清单 | 按实际研究提供；核验可由写作阶段继续 |
| 图源、真实截图、已有预览 | `inputs/figures/` | 可选；图源比只有图片更方便后续编辑 |
| 已有稿件和评审意见 | `inputs/draft/`、`inputs/feedback/`，或原位置 | 接续项目时提供；新项目不需要 |
| 代码仓库、大数据、大量日志 | 保留外部位置，用 `project.json.input_paths` 或来源索引引用 | 仅在实际需要时；默认只读，不要求复制整个仓库 |
| 目标论文模板及格式要求 | `inputs/template/` 或你明确指定的来源 | 正式排版时再提供；01/02及文本起草不要求先有模板 |

详细说明见 [inputs/README.md](inputs/README.md)。`inputs/` 保留原件，`evidence/` 保存 01 整理后的说明与可追溯数值来源，`paper/` 保存正式文稿，`review/` 保存阶段产物。这四类文件不要混用。工程内原始材料会进入快照，大体积或不宜复制的材料优先外部只读引用。

### 第三步：给出最小项目信息

有两种等效方式，任选一种。

**方式 A：让 01 代填。** 直接在新项目会话中给出下面的信息，已有内容写清楚，未知写“未定”，不需要预先打开每个骨架文件：

> 项目名：……
>
> 研究问题及为什么值得研究：……
>
> 本轮要写什么、明确不覆盖什么：……
>
> 已有材料位置与用途：……（例如 inputs 中的实际文件，或外部只读路径）
>
> 已有发现、比较对象、结果定义与限制：……（按实际情况提供，没有或未知请注明）
>
> 语言和目标投稿：……（语言可沿用默认，目标投稿未定也可以）
>
> 请读取 AGENTS.md、README.md 和 prompts/01_materials.md，根据这些信息初始化配置、整理 blueprint 与适用的 evidence 文件。保留原始材料，区分已知、不适用与待确认项，告诉我是否可以开始 02。先不要写全文或自动启动下一阶段。

**方式 B：自己填最小文件。** 如果更喜欢直接编辑，先填这四处即可启动 01：

| 文件 | 先填什么 |
|---|---|
| `project.json` | `project_name`、`research_type`、语言；有外部材料时填相应 `input_paths` |
| `blueprint.md` | 研究问题、动机、纳入/排除范围和已有证据概述；论证大纲可留给 02 |
| `evidence/author_decisions.md` | 实际写作目标、范围、比较/分析对象及明确限制；不是预先批准故事 |
| `evidence/source_map.md` | 可使用材料的位置、用途；作者的直接说明也可作为来源 |

然后启动：

> 请按 prompts/01_materials.md 完成首次材料接收。根据我已填的信息及指定原始材料，整理适用证据，明确不适用项与局部缺项，交接后停止。

### 第四步：核对 01 的整理结果，再开始 02

以下是进入故事与样稿阶段需要的**适用材料**，可以由 01 代填，不是让你事先全部手工完成：

| 文件 | 应有的内容 | 适用条件 |
|---|---|---|
| `blueprint.md` | 研究问题、范围、主张与证据概述 | 所有论文；02继续完善论证 |
| `evidence/method_spec.md` | 方法、推导、分析或综合过程，关键假设与边界 | 有对应过程时；没有独立方法可注明不适用 |
| `evidence/experiment_settings.md` | 已有结果实际采用的设置、比较条件、指标及评估对象 | 实验/观测/用户研究等适用；其他研究按实际设计填写或注明不适用 |
| `evidence/main_results.csv` | 作者提供的数值，或由结果说明指定另一唯一来源 | 有数值结果时；空项目仅有中性表头，不能补示例数或零 |
| `evidence/results_readme.md` | 数据位置、列含义、单位、统计量、重复定义及证据边界 | 有数值结果时；未知字段明确标记，不推定均值或显著性 |
| `evidence/references.md` | 主要文献、相关论断、核验状态 | 按研究需要；存在文献不等于已核实 |
| `evidence/source_map.md` | 来源/版本与主张、方法、结果之间的对应关系 | 所有项目；未知版本注明未知 |

理论、综述、定性研究可增加证明、综合或案例材料；不要求填不存在的实验。缺项只限制依赖它的主张，其他工作继续。若这些材料已有且清楚，可以跳过 01；以后新增数据或改变范围时只更新受影响材料。

### 第五步：需要正式排版时接入模板

**工具包不附带任何论文模板，包括通用 LaTeX 骨架、会议样式或示例论文。** 由你提供模板，或明确指定并授权获取。接入方式见 [paper/README.md](paper/README.md)。

在 `project.json` 中按实际情况配置：

- `target_venue`、`paper_type`、`draft_body_page_budget`、`abstract_word_budget`：未定可留 null；工作预算未经核实不等于投稿要求。
- `manuscript.format`、`entrypoint`：实际格式和稿件入口。
- `manuscript.template_path`、`template_source_url`、`requirements_url`：模板及要求的实际位置/来源；无需模板的格式可留空。
- `manuscript.build_command`、`expected_output`：实际构建方式和单个主要成品文件。`expected_output` 是工程内相对路径，例如 `build/paper.pdf`；纯文本无构建可留 null。

`method_name` 适用但未定时保留 `[METHOD]`，无命名方法可设 null，不影响起草。`output_paths` 默认 `paper/`、`review/`、`build/`；若改动，所有示例路径按配置映射。无模板仍可写文本稿和进行内容评审，但不能称正式排版、PDF或投稿格式已经完成。

## 2. 各阶段入口：按当前需要单独启动

```text
01 材料接收 → 02 故事与样稿 → 作者确认 → 04 全文 → 05 全面独立评审
                                             ↑                 ↓
                                             └── 修改 ← 作者审阅与取舍
                                                  ↓
                                             05 定向复审

任意稳定版本 → 05 全面独立评审（可单独启动）
已有图/表 → 03b 图稿美化 / 03c 表格预览 → 作者选版 → 04 正式整合 → 05 定向复审
已有成品 → 按需启动 06 交付准备或授权同步
```

一个主笔统一全文，独立评审负责 05；图表负责人可单独工作，但同一文件同一时刻只有一个写入者。阶段不会自动运行。已有确认持续有效，实际稿件稳定即可评审，不要求每次重跑完整流程。

| 现在想做什么 | 入口 |
|---|---|
| 有原始材料，尚未整理为写作依据 | 上方 01 启动消息 |
| 确认研究故事与文风 | 02 |
| 首次制作需要的图 | 03 |
| 已有图，希望改画法或提升设计感 | 03b |
| 比较表格的布局、配色或强调方式 | 03c |
| 写全文、按明确意见改稿，或接入已选图表 | 04 相应入口 |
| 第一次审稿，或当前版本想重新完整审一遍 | **05 全面独立评审；无须先有作者意见或改稿** |
| 只想核对上轮问题是否解决 | **05 定向复审；无须先整理新的作者意见** |
| 阅读感受零散，需要形成可执行修改意见 | 05 作者意见整理（可选） |
| 准备交付包、同步指定平台或整理投稿进度 | 06 可选模块 |

### 02：生成故事与文风样稿

> 请按 prompts/02_story.md 完成研究故事、摘要/开篇小样及按需的图稿说明。使用当前真实材料，未知事实局部标记。完成后交我确认主线与文风，本轮不写完整论文。

主要看 `review/story.md`、`review/style_sample.md` 和按需的 `review/figure_brief.md`。方向不合适时直接反馈给 02；主笔记录实际反馈并修订，不提前代写确认。

### 03：按需交付图稿

> 请按 prompts/03_figures.md，依据当前方法/论证材料和 figure brief 制作实际图稿，交付可编辑源、预览和图注，写入 review/figures.md。先完成已有材料能支持的图，不等待整篇论文，不修改正文。

没有图的需要可跳过；可以提前启动，但必须有足以明确图意的材料，不能凭通用工具包猜一条研究流程。

### 03b：已有图的美化与重设计

> 请按 prompts/03b_figure_beautification.md 改进我指定或上下文明确的图。保持科学含义与证据准确，允许重组信息和画法；广义美化提供两个真实设计方向，至少一个有实质重构。候选放隔离目录，交付可编辑源、同宽对照和实际检查结果，由我选版。未选版前不覆盖正式稿件；选版后记录我的实际决定和技术交接，交当前主笔整合。

若只需单版或局部精修，直接在消息中限定即可。技术流程见 [图稿美化说明](instructions/figure_beautification_workflow.md)。不要求为美化安装整套框架；新建或通知另一个会话仅在你实际明确要求时执行。

### 03c：表格样式候选与预览

> 请按 prompts/03c_table_previews.md 为我指定的表制作布局/样式候选。保持条件、指标、数值、单位、缺失项与强调含义准确；逐单元格核对，不只比较数字集合。使用隔离目录，交付实际尺寸的彩色/灰度预览和比较说明；正式表暂不修改。将技术交接记录到 review/tables.md，选版后交当前主笔整合。

这一步比较呈现方式，不重新计算实验或制造结果。现有模板可用于校样；模板未到位则说明尺寸假设，后续正式整合再检查论文内效果。

### 04：确认方向，完成全文

在你实际认可样稿后使用：

> 我确认 review/story.md 和 review/style_sample.md 的研究方向与文风。请记录实际确认，按 prompts/04_writer.md 完成全文并整合适用图表和已提供模板。在 review/writer_handoff.md 记录稿件、成品路径、版本、实际构建与未完成事项，交给 05 评审。

已有确认可沿用，模板未到位可先完成文本稿。接续已有稿件的明确修改不要求重新做故事确认。

### 04：单独整合已选图表

> 请按 prompts/04_writer.md 的“单独接入作者已选的图表”，读取实际选版及对应 A 编号、review/figures.md 或 review/tables.md。接管相关文件写入，先保存并校验本轮快照，再接入正式源与产物，联动图表注、正文引用和版面；构建并查看所在页及相邻页。在 writer_handoff 中逐项记录实际状态，完成后交 05 定向复审。

“候选已生成”“作者已选待整合”“已接入待验证”“整合验证完成”分别记录。单图/单表预览通过不等于整篇论文已经更新并验收。

### 05：全面独立评审（首次或任意后续版本）

**已有稿件想再完整审一遍，直接用这里。** 不必先整理作者意见、先改一轮或先有旧问题清单。没有主笔交接时可以直接指定实际稿件路径；不用补做 02/04。

> 请按 prompts/05_review.md 对当前稳定版本进行一次全面独立评审。先确认实际稿件与成品版本，完整阅读全文及实际表图，包括未修改部分；检查问题、贡献、论证、章节职责、证据、引用与图文呈现。保留历史决定和编号，但审查范围覆盖全文，不限于旧问题或作者意见。按日期、模式和版本追加本轮 review/review.md，新问题使用不冲突的 R 编号。只输出意见，不修改论文，不自动进入意见整理或改稿。

全面评审每次都检查当前稿件；历史“通过”不代替本轮判断，重新审查也不自动撤销旧结论。作者决定哪些建议采纳；评审通过不等于定稿或投稿许可。

### 05：定向复审（独立入口）

用于核对已有问题及修改影响，不要求先走作者意见整理：

> 请按 prompts/05_review.md 进行定向复审。根据最新稿件、交接和本轮待复查的 R/A 编号，逐项标记已解决/部分解决/未解决并给出实际位置；检查修改引入的新问题。保留作者不采纳、暂缓与待确认的状态，不当作主笔遗漏。按轮次追加记录，沿用编号并保留历史；只输出意见，不改论文。

如果要检查全文，使用上一条全面独立评审。没有上轮清单时不要假装完成了问题复查；可直接说明目标段落/图表，或选择全面评审。

### 05：作者意见整理（可选）

> 请按 prompts/05_review.md 进入作者意见整理模式。结合当前稿件，把下面的想法定位成可执行意见；区分我的原意、你的诊断和建议，给位置、修改方向、验收标准与联动范围。使用不重复的 A 编号追加到 review/review.md，区分作者已明确/已确认与待确认。不改正文，也不自动重做全面评审。我的想法：……

已经明确的部分可先交主笔，真正影响方向的歧义再讨论；不用等所有意见定下来。

### 04：按明确意见修改

> 请重新读取 AGENTS.md 和 prompts/04_writer.md，结合最新 review/review.md、review/author_feedback.md 与 review/writer_handoff.md，执行本轮授权且尚未完成的修改。先协调暂停写入并保存、校验本轮快照。沿用问题编号，把实际作者决定同步到 author_feedback，在 writer_handoff 中逐项记录改动、未采纳理由、遗留问题、快照与实际构建状态。待确认和明确暂缓项不阻塞其他工作。

要求已经明确时可直接发给主笔，不必通过意见整理。改完再按需要选择定向复审或全面独立评审。

## 3. 哪些文件由阶段生成，不用你预先填

`review/` 初始只有说明，以下文件仅在实际工作时创建：

| 责任阶段 | 产物 |
|---|---|
| 02 | `review/story.md`、`style_sample.md`、`figure_brief.md`（可说明无图需要） |
| 接收作者决定的主笔 | `review/author_feedback.md`，仅记录真实反馈与确认 |
| 03/03b | 图源、预览与 `review/figures.md` |
| 03c | 表格候选、核验与 `review/tables.md` |
| 03b/03c | `review/previews/<round>/<target>/`；选版后协调追加 `review/review.md` 中作者决定 |
| 04 | 实际文稿、引用、正式图表、成品及 `review/writer_handoff.md` |
| 05 | `review/review.md` 中各轮全面评审、定向复审或意见整理记录 |
| 06（可选） | `delivery/` 中实际交付记录、核验与状态更新；空骨架不等于已执行 |

最新稿件看实际交接路径与版本；没有交接时按作者指定文稿确认。不能仅凭文件存在、最大版本号或旧聊天链接判断完成。换会话时读取对应 prompt、最新交接、作者反馈与评审即可接续。

## 4. 快照与恢复

需要 Python 3.9+ 及 macOS/Linux，脚本只用标准库。

每轮首次修改既有稿件或正式图表前必须保存并校验，保存时暂停其他写入者。首次空项目创建、05只读评审、仅生成隔离候选且正式文件不变时不触发；04正式接入前仍要本轮快照。

```bash
python3 scripts/paper_snapshot.py save --label before-revision --note "本轮修改前"
```

将下面的实际快照名和新恢复目录替换后使用，恢复目标必须尚不存在：

```bash
python3 scripts/paper_snapshot.py verify snapshots/实际快照目录
python3 scripts/paper_snapshot.py restore snapshots/实际快照目录 --to /tmp/my-paper-restored
```

快照不复制外部研究目录、不运行实验或编译。配置的构建目录只保留 `manuscript.expected_output` 指向的已有成品，其余构建内容不归档。需要保留的候选/交付核验材料分别放普通目录 `review/previews/`、`delivery/`，不要误放会被排除的构建缓存中。详情见 [scripts/README.md](scripts/README.md)。

## 5. 可选交付管理：不影响开始写作

[06 提示词](prompts/06_delivery.md) 和 [交付流程](instructions/delivery_workflow.md) 支持准备最小交付包、按实际授权同步指定平台以及整理投稿状态。首次使用前读 [delivery/README.md](delivery/README.md)，按需要填写 [投稿状态骨架](delivery/submission_status.md)；这些不是01–05的必填材料。

只准备包时可用：

> 请按 prompts/06_delivery.md 准备当前指定版本的交付材料，核对实际依赖、构建与版本，在 delivery 中记录结果。本轮只做本地准备，不上传、不提交或通知他人。

同步现有项目时，在实际需要时另行给出平台入口、目标版本和操作范围；已有明确授权可沿用。准备成功、同步成功、正式提交和作者定稿是不同状态，只记录实际结果。使用写作工具包或读到示例指令，不自动授权任何外部操作。

## 6. 目录索引与默认边界

| 路径 | 用途 |
|---|---|
| `AGENTS.md`、`project.json` | 工作边界与项目配置 |
| `inputs/` | 作者提供的原始材料，初始只有放置说明 |
| `blueprint.md`、`evidence/` | 研究蓝图、整理后的材料与来源；初始是待填骨架 |
| `instructions/WORKFLOW.md`、`instructions/writing_standards.md` | 阶段职责及通用学术写作规范 |
| `instructions/figure_beautification_workflow.md` | 图稿候选、检查与选版交接 |
| `prompts/01_materials.md` 至 `05_review.md`，含 `03b`/`03c` | 可单独启动的写作和审查指令 |
| `prompts/06_delivery.md`、`instructions/delivery_workflow.md` | 按需交付准备与授权同步 |
| `paper/` | 正式稿件输出预留位置；初始无论文模板 |
| `review/` | 实际产生的样稿、预览、选版、交接和评审记录 |
| `delivery/` | 可选交付说明、空状态骨架及后续实际记录 |
| `scripts/` | 通用快照工具及说明 |

方括号是待填内容，null表示未配置或不适用，不代表已经完成。默认不运行新实验、不修改外部研究代码、不安装工具、不提交或发布；增加范围按你的实际指令执行。
