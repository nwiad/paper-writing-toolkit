# 新项目的原始材料放这里

本目录初始只有说明，没有真实研究材料。这里用于接收作者提供的原件；01 只读提取内容，将整理结果写入 `evidence/` 并登记来源，不改写原件。

你不必准备全部类型，也不必使用下面的文件名。优先放已有材料，缺什么由 01 具体说明。

| 你已有的材料 | 建议位置（由你实际放入后才存在） | 用途 |
|---|---|---|
| 研究想法、方法说明、实验说明、笔记 | `inputs/research_notes.md` 或原文档 | 确定问题、范围、过程和已知事实；也可直接在启动消息中说明 |
| 已有结果表及作者对数字的解释 | `inputs/results/` | 保留原 CSV/XLSX/文档等格式；说明单位、统计量、重复定义，未知不要猜 |
| 关键论文与引用线索 | `inputs/references/` 或链接清单 | 核验相关工作和论断；文件存在不表示引用已核实 |
| 图的可编辑源、截图/证据及预览 | `inputs/figures/` | 按需制图、重设计或核验科学含义；没有图可跳过 |
| 已有文稿、作者意见、历史审稿 | `inputs/draft/`、`inputs/feedback/` | 接续写作或独立评审；不是新项目必须有的材料 |
| 你选定的论文模板及要求 | `inputs/template/` 或明确的外部位置 | 04 正式排版时接入；工具包本身不提供模板，01/02不依赖它 |

大数据、代码仓库、大量日志及不宜复制的资料继续留在原位置。填写 `project.json.input_paths`，或在启动消息/`evidence/source_map.md` 中给出只读路径与用途。不要用符号链接把外部仓库挂进本目录；现有快照工具会拒绝归档符号链接。没有代码仓库、原始日志或数值结果不自动阻止写作。

快照会收录工程内普通材料，因此不建议把整个研究仓库或大体积数据复制进 `inputs/`。保持一份唯一原件，在整理材料中引用来源，不为不同阶段复制多份结果。

如果从已有文稿开始，只需指出实际稿件及本轮目标；作者要全面评审时可直接启动 05，不用先补出 02 的故事、04 的交接或假装它们已完成。修改现有稿件前仍遵守快照规则。
