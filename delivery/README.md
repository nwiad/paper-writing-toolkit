# 可选交付与投稿状态目录

此目录保存已有稿件的交付材料、平台同步记录和投稿状态。它不包含稿件、论文模板、授权、真实投稿或核验结果；不影响 01–05 的正常写作流程。

需要时启动 `prompts/06_delivery.md`，细则见 `instructions/delivery_workflow.md`。可只做本地准备，也可在作者实际授权后同步指定现有项目（例如 Overleaf），或仅整理投稿状态。已有稿件可直接进入本阶段，无需补造历史写作阶段产物。“准备交付”不自动授权上传、正式提交或通知他人。

## 需要提供的材料

- 本轮目标稿件、版本依据及实际入口；路径从 `project.json.manuscript` 和 `output_paths` 读取，模板由当前项目提供。
- 已有成品及构建方式；没有成品或构建环境时如实标记，仍可整理已有源码。
- 需要平台同步时：作者指定的目标入口和允许的操作范围，存在时提供上次已确认同步的基线。
- 需要登记投稿状态时：目标官方要求、实际状态来源、待办和截止时间；尚未知的项目保留待填写。

## 本轮目录

实际执行时才建立新的 `delivery/<round>/`，不提前生成真实轮次。以下只是目录约定：

| 路径 | 实际发生时保存的内容 |
| --- | --- |
| `downloads/before/` | 更新前直接下载的源码、成品和必要日志 |
| `downloads/after/` | 更新后回下载用于核验的文件 |
| `downloads/failure/` | 故障后、恢复前直接下载的状态证据 |
| `backup/` | 已检查的基线备份及设置记录 |
| `staging/` | 预期交付状态的完整最小依赖 |
| `upload/` | 本轮新增或替换文件；删除和改名单独列清单 |
| `online/` | 回下载源码的独立解包副本 |
| `compile/` | 独立副本的构建日志、中间产物和成品 |
| 本轮清单与记录文件 | 来源和目标路径、SHA-256、冲突、授权范围、核验与恢复依据 |

首次下载前必须建好专用下载目录，并确认能直接保存到其中；不先下载到系统目录再补搬。不覆盖历次备份，不复用旧成功结论。

这里的 `delivery/` 是工程根目录下普通材料目录，与可配置的 `output_paths.paper/review/build` 分开。重要记录不要移进构建目录：现有快照脚本对构建目录通常只保存 `manuscript.expected_output` 指向的文件。快照不会自动发生；需要阶段备份时按工程规则运行快照脚本。

## 当前状态表

`submission_status.md` 初始只有空白字段骨架：稿件“未配置”，投稿“未登记”。按本项目官方要求和实际凭据填写；不要将占位符、模板示例或旧项目状态当成事实。保持当前状态简明，详细过程链接本轮记录。
