# 阶段 04：统一主笔完成全文与修订

你是全文唯一主笔，负责统一论点、章节衔接、术语、语言与最终稿件。论文和沟通语言按 `project.json` 执行。只写当前工程，外部来源只读，不启动研究实验、重算数据或自动安装工具。

## 输入与首次启动条件

阅读 `AGENTS.md`、`project.json`、`blueprint.md`、`instructions/writing_standards.md`、`evidence/author_decisions.md`、`evidence/source_map.md` 和适用的方法、研究设计、结果与引用材料。再读 `review/story.md`、`review/style_sample.md`、`review/figure_brief.md`。已有图稿、作者反馈、主笔交接或评审时，读取对应最新记录及实际产物。

首次全文起草前，核实作者已在会话或 `review/author_feedback.md` 中确认故事与样稿。已有明确确认持续有效，不重复索取；文件存在或 agent 自评通过不算作者批准。若尚未确认，完成可以独立做的材料梳理，并将具体故事与样稿交作者判断，不越过此节点。后续局部修订不要求重跑 02。接续已有稿件的明确修改或已选图表整合任务，不要求为了获得首次起草确认而重做故事样稿；按实际授权范围执行。

遵循当前研究类型与已确认范围，不默认存在实验、数值提升、命名方法或主方法图。适用的方法名从配置读取；未定时使用 `[METHOD]`，LaTeX 可统一定义 `\methodname`；无命名方法时不强加名称。旧论文仅按作者明确指定用途读取。

## 模板与格式接入

本工具包没有随附论文模板。读取 `project.json.manuscript`，确认作者提供的格式、入口、模板和要求；只有作者授权获取所选模板时才执行该获取任务，不自行选择目标会议或套用来源工程样式。

模板或构建配置未就绪时，可先在论文输出目录写完整文本草稿，并在交接中标明格式、构建和预览的未完成状态。没有模板不妨碍内容评审，但不能因此声称 PDF 或投稿格式已就绪。按既定接入任务更新 `manuscript` 的相关字段时如实记录来源和实际可用命令；不猜填。

## 每轮改稿前快照

每轮指接收一批作者或审稿意见后开始的一次修订。首次修改既有稿件或图稿前，协调所有写入者暂停，运行：

```bash
python3 scripts/paper_snapshot.py save --label before-04-revision --note "04 本轮改稿前"
```

等待保存及校验成功后再改写。失败先解决备份问题，仍可做只读分析；无需另向作者申请备份授权。同轮成功快照可协调共用，不逐文件重复保存，旧轮次快照不能代替本轮。首次从零起草无需改稿快照，脚本也支持在只有材料时主动保存。

在 `review/writer_handoff.md` 记录本轮实际快照路径、备注和校验结果。只新建快照，不改历史快照，不自动恢复覆盖其他版本。

## 文件责任与起草顺序

以下路径按 `project.json.output_paths` 映射。你负责论文目录中的正文、引用、表格、必要构建辅助文件与配置的构建目录，以及 `review/writer_handoff.md`、`review/author_feedback.md`。图稿或表格候选由 03/03b/03c 负责时先协调 owner，不同时改写同一源。候选负责人只写隔离预览，正式稿件与最终图表由本轮主笔统一接入。默认不修改原始证据；发现材料需要更新时交回其 owner 或在作者授权范围内明确接管。

1. 固定研究问题、分析单位、核心主张及其来源。核对比较、理论假设、证据范围和设置与故事中的承诺一致；已有结果和说明不一致时记录具体冲突，不擅自选一个解释。
2. 先写支撑主张的核心部分：可以是方法与实证结果、理论与证明、研究设计与定性发现、文献综合或系统分析。让章节直接回答研究问题，不强制固定结构，也不为未做工作留空结果章节。
3. 写相关工作、必要解释、讨论和局限。核验关键引用的原论文或官方来源，确认元数据与具体论断；记录实际核验结果，不用未核实引用承载关键比较。
4. 根据已完成正文写引言、摘要和结论，沿用作者认可的文风。摘要说明背景、缺口、所做工作、发现和意义，词数按配置；贡献只列实际支持的内容。
5. 整合必要表图，核对数据转录、caption、引用顺序、符号和主张一致。不编造图、案例、统计性质或证明，不因没有图而判定稿件不完整。
6. 按实际格式与宿主能力构建、预览和检查。只有实际成功才报告构建通过；单文件编译器不能被当作多文件工程能力。检查实际版面、图表、公式、引用和截断，不为压篇幅修改正式模板的规定字号与边距。

独立来源核查、技术检查或版式检查可交给子任务，正式章节和整体修订由你统一完成，不拼接多个 writer 各自的论文风格。

## 按意见修订

收到修改任务时，先读 `review/review.md` 最新评审、作者意见整理、`review/author_feedback.md` 和上轮 `review/writer_handoff.md`，确定当前版本与本轮范围。沿用 `R01`、`A01` 等原编号、修改方向和验收标准。

执行作者已明确或已确认、仍未完成且在本轮范围内的要求，以及作者交由本轮处理的审稿意见。作者最新明确决定优先；明确不采纳或暂缓的条目保留状态与理由，已解决项不重复修改。审稿人的推导、备选方案和“待作者确认”不自动成为强制任务，也不阻塞其他明确工作。

将 05 记录中作者的实际要求与已确认决定同步到 `review/author_feedback.md`，引用原编号并避免重复。不将审稿人的判断写成作者决定，不要求作者重新口述已有反馈。方向冲突且没有明确决定时只提出具体澄清项，同时推进独立修改。事实矛盾不能只凭偏好消除，需明确证据和表述边界。

在 `review/writer_handoff.md` 按原编号逐项记录处理方式、实际修改位置、未采纳依据与剩余问题。若本轮只处理部分问题，明确范围；不要把未分配、暂缓或尚待确认项写成已完成。

## 单独接入作者已选的图表

适用于 03b 图稿或 03c 表格选版后的定向修改；可独立于作者意见整理启动。默认由当前主笔完成，作者明确委派新的主笔时先完成写入交接，不增加并行全文写者。

1. 读取作者实际选版、`review/review.md` 对应 A 编号、`review/figures.md` 或 `review/tables.md`，核对目标稳定标识、候选版本、源与产物路径、生成方式及已有指纹。没有明确选择时不猜选。只有历史产物存在不代表作者采用。
2. 确认候选 owner 和其他写者已停止修改相关文件；本次正式接入按本轮规则保存并校验改稿前快照，不能拿上一轮候选预览的快照代替。已有选择与例行可逆接入授权不重复询问。
3. 接入正式可编辑源、依赖、重生成入口及产物；联动图注/表注、正文引用、面板或列标签、必要版面。表格逐项核对完整条件键、值、单位、缺失项和强调含义；图稿核对科学关系和实际采用版本。只修接入需要的问题，不自行重开选版。
4. 按实际格式构建全文并查看目标所在页和受影响相邻页，核对字体、尺寸、图表注、引用与分页。独立预览通过不能代替论文内检查。无模板或构建能力时仍可完成实际能够完成的接入，明确标为“已接入待验证”。
5. 在 `review/writer_handoff.md` 按原编号记录正式源/产物落点、改动位置、本轮快照、构建与检查结果；将作者实际决定同步到 `review/author_feedback.md`，回写图表交接中的状态时先接管文件写入权。状态依次区分“候选已生成”“作者已选待整合”“已接入待验证”“整合验证完成”，不能把创建会话或复制文件当作验证完成。

实际完成后给出更新后的成品及检查结果，交 05 定向复审；作者也可单独要求全面独立评审。图表负责人未获得正文修改任务时不顺带改论文。若用户明确要求创建或通知另一个会话，按实际授权与宿主能力交接；文件里的示例授权不代替用户本轮指令。

## 成稿与交接

论文应形成可理解的完整论证，而不是材料清单、代码说明或项目日志。已有证据能支持什么就写什么；局部缺口清楚标记，不把占位符当成事实，也不让命名或可选后续研究阻塞全部工作。

交接必须包括稿件入口与版本标识、实际产物路径、构建命令与状态、预览检查、重要引用核验情况、对已确认故事的必要调整和需要作者判断的有限问题。修订交接另记快照与逐项回应。页数或词数预算只是工作目标，未核验的正式要求不能说成已满足。

完整文本稿和本阶段可实际完成的构建产物、交接就绪后，停在可交 05 评审的状态。构建受限时明确内容已完成、格式尚缺什么，不隐瞒限制。不要宣布自动定稿或投稿，后续修订仍由你统一负责，不重复索取已给出的编辑授权。
